# Other decimal operations

The four unary operations validate the metadata through `s21_unpack` and use the existing big-word implementation. Arithmetic and common production files are unchanged.

## Policies

- `s21_negate` flips only bit 31 and preserves the coefficient and scale, including signed and scaled zero.
- `s21_truncate` discards fractional digits toward zero.
- `s21_floor` rounds toward negative infinity, including negative fractions smaller than one.
- `s21_round` rounds to the nearest integer, with exact halves away from zero. This is distinct from the banker's rounding used in arithmetic packing.
- Integer-producing operations return scale zero and positive zero.
- A null output or invalid reserved bits/scale returns 1. Invalid input clears a nonnull output.
- Input is passed by value; output may point to the original input.

The integer tables contain independently computed exact integer expectations, not results generated by the library under test. They exercise both signs, scales 0 through 28, full 96-bit coefficients, maximum magnitude, carries across word boundaries, trailing zeros, and values around half-integers. Error tests exercise every reserved flag bit and every invalid scale from 29 through 255 with both signs. Each public function was added in its own failing-link/test-first implementation slice.

## Build and verification

Run from `src`:

```sh
make clean
make all
make test
make test-sanitize
make gcov_report
make test
```

Dependencies: a C11 compiler, `ar`, `pkg-config`, and the real Check library. HTML coverage additionally requires `gcovr` and a compatible gcov executable. No dependencies are installed by the Makefile. The old `check_compat` files are retained but neither included nor linked.

Tests link `s21_decimal.a`, not loose production sources. Dependency files track header changes. Normal, sanitizer, and coverage builds use separate object directories and separate instrumented archives; coverage does not replace the public normal archive. HTML starts at `.build/coverage/index.html`; machine-readable counts are in `.build/coverage/coverage.json`. `make clean` removes these artifacts.

`make test-sanitize` defaults to fail-fast UndefinedBehaviorSanitizer. Override `SANITIZERS`, `SANITIZER_OPTIONS`, or `ASAN_OPTIONS` explicitly as needed:

```sh
make test-sanitize SANITIZERS=address,undefined
```

Leak detection defaults off on macOS and on elsewhere. Check runs without forking for sanitizer and coverage builds. On this macOS host the address+undefined executable built successfully but did not start emitting test output before a 120-second timeout; no AddressSanitizer pass is claimed. The default undefined-only run works.

Clang coverage uses `xcrun llvm-cov gcov` on macOS and `llvm-cov gcov` elsewhere; GCC uses `gcov`. Override `GCOV` when tool locations differ:

```sh
make gcov_report GCOV='xcrun llvm-cov gcov'
```

Each `other/s21_*.c` file contains exactly one public function, so its executable-line counts in the JSON report directly measure that function rather than an aggregate containing unrelated helpers.
